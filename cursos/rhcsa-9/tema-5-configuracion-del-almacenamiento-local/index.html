1. Listar, crear y eliminar particiones GPT

Antes de poder utilizar un disco debemos crear particiones. El estándar actual es GPT, que sustituye a MBR, aunque este se sigue usando.

Las diferencias principales entre MBR y GPT son que MBR está limitado a 2TB y 4 particiones, mientras que GPT permite discos más grandes, particiones casi ilimitadas y mayor recuperación de datos.

Para listar los discos o particiones que tenemos podemos usar los siguientes comandos, que cualquiera es valido para hacer comprobaciones :

  • lsblk → Vista clara de discos y particiones.
  • blkid → UUID y tipo de filesystem.
  • parted -l → Información de tabla GPT/MBR.
  • fdisk -l → Información técnica detallada.
  • df -h → Espacio usado en sistemas montados.

Las particiones pueden gestionarse con fdisk, gdisk o parted (recomendado en Red Hat). Tras modificar particiones ejecutamos partprobe para actualizar el kernel.

Una vez listados los discos, podemos crear o eliminar particiones usando fdisk, gdisk o parted. Tened en cuenta que gdisk funciona practicamente igual que fdisk.

Para usar fdisk ejecutamos fdisk /dev/sdX (el disco se obtiene con fdisk -l) y desde el menú interactivo podemos crear o borrar particiones.

Con n creamos particiones, con d las eliminamos y con t cambiamos su tipo.

3. Crear y gestionar grupos de volúmenes (VG)

Un Volume Group combina varios PV creando un espacio de almacenamiento común.

En los VG entra el concepto de PE que es la unidad basica de almacenamiento en LVM. Nosotros asignamos X tamaño pero internamente LVM utilizará los PE. Por defecto son 4MB, entonces si por ejemplo tenemos 10GB, LVM usará 2560PE (10GIB / 4MB)

Vemos com hemos creado, extendido, reducido y borrado VG, así como comprobado con vgs o vgdisplay. Por ultimo, podriamos activar o desactivar con vgchange -ay/-an nombre-VG, siendo -ay para activar y -an para desactivar

5. Montar sistemas de archivos usando UUID o LABEL

El montaje persistente se configura en /etc/fstab. Se recomienda usar UUID o LABEL para evitar problemas si cambia el nombre del dispositivo.

En cuanto las LABEL(etiquetas) podemos asignarlas de diferentes maneras

  • mkfs.ext4 -L NOMBRE DISCO → Crear filesystem con etiqueta. Es la más recomendada
  • tune2fs -L → Cambiar etiqueta en EXT.
  • swaplabel -L → Etiquetar SWAP.
  • blkid → Obtener UUID.

La sintaxis para montar un sistema de archivos de forma automatica al arrancar el sistema es : [dispositivo] [montaje] [fs] [opciones] [dump] [pass] (donde dump es siempre 0 y pass(verificar un filesystem al arrancar) suele ser 0 (no verificar) o 2 (verificar en segundo lugar). Las opciones, si no dicen lo contrario, usar defaults

6. Cambios no destructivos y configuración SWAP

Los cambios no destructivos consisten en ampliar almacenamiento sin perder datos mediante vgextend y lvextend -r. Reducir incorrectamente puede provocar pérdida de información.

Uno de los mayores errores que hace que sea destructivo es una vez hemos extendido o reducido, formatear el disco mkfs, ya que borraría todos los datos. El otro error sería borrar la tabla de particiones o la partición con fdisk o parted.

fallocate -l 1G /swapfile #FORMA RAPIDA

mkswap /swapfile
swapon /swapfile
echo "/swapfile swap swap defaults 0 0" >> /etc/fstab
